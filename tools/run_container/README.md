# SPECTRE run container

This folder contains the configuration files to build a Docker image with SPECTRE pre-installed and ready to use.

The image is built in three stages to minimise its final size:

1. **`spack-builder`** — builds the runtime dependency stack (GCC, OpenMPI, HDF5, OpenBLAS, FFTW, Python) using Spack.
2. **`spectre-builder`** — compiles and installs SPECTRE (Fortran extensions + Python package) into `/opt/spectre-env` using `uv`.
3. **Final image** — bare OS with only the Spack runtime libraries and the installed SPECTRE environment; no compiler, no build tools, no module system.

## How to build

The build context must be the **repository root** so that the SPECTRE source is available:

```bash
docker build -f tools/run_container/Dockerfile -t spectre-run .
```

## How to run

Interactive shell (SPECTRE and all runtime libraries are on the path):

```bash
docker run -it --rm -v $(pwd):/data spectre-run
```

Run a script directly:

```bash
docker run --rm -v $(pwd):/data spectre-run python /data/my_script.py
```

## How does it work

The dependency stack is defined in `spack.yaml` and built from source by Spack. The activation script generated by Spack (`z10_spack_environment.sh`) sets `PATH` and `LD_LIBRARY_PATH` so the compiled Fortran extensions can find their shared libraries at runtime. The entrypoint script sources this activation script before executing the requested command.

### `spack.yaml` variables

- `core-packages`: packages compiled once (cmake, used only during the SPECTRE build stage).
- `packages`: compiler-dependent runtime libraries (HDF5, OpenMPI, OpenBLAS, FFTW, Python, NumPy, mpi4py).
- `compilers`: the compiler used to build the stack (GCC 13.2.0).
